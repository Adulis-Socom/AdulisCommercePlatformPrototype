# Background-removal experiment (prototype only)

A small local adapter around `rembg` 2.0.88 for two prototype tools: the **Background Removal Lab** (Prototype Guide >
Experimental Tools) and Seller Console > Products > Media. It is a research tool, not part of any production system.

- Runs only on this computer (`127.0.0.1:8765`). Photos are never sent to an online service, and no remote provider is active.
- The prototype works normally without it; the Lab and the Media panel then say the adapter is not running.
- **Three models are admitted, for internal evaluation only** (`birefnet-general-lite`, `birefnet-general`, `sam`; lead decision 2026-11-28, reversible by the founder; see "Admitted models" below). `models.json` is the single registry of all 23 rembg sessions. Every entry has a status;
  only exactly `"admitted"` can load, a status alone is not enough (schema 3, below), and there is no environment-variable or flag override. Evidence and reasons:
  `Deliverables/Prototype/PROTO-AUTONOMOUS-002/MODEL_ADMISSION_REGISTER.md`. A model that is not admitted is listed in the Lab with its reason and cannot be selected or run.
- The limits (10 MB, 16 megapixels, 60 s, one image at a time, one model cached) are experiment defaults, not product policy.

## One-time setup (Windows, Python 3.11 to 3.13)

```
cd tools\bg-removal
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

`setup_models.py` downloads only models that are `admitted` with `installPermitted` (none has it: admitted files come from quarantine through `promote`). A permitted model can also be
installed through `POST /install`, which refuses anything not admitted (schema 3) and `installPermitted`. Before any download or load the
adapter checks free disk and free RAM and refuses with 507 rather than risk the machine. The `.venv` and `models` folders are git-ignored.

## Quarantine, admission and promotion (PROTO-BGR-RESEARCH-001)

Acquiring a file for **inspection** is separate from admitting it for **execution**.

- `models/quarantine/<model-id>/<file>` holds downloads that are for inspection only, listed in `models/quarantine/MANIFEST.json`, a list of
  `{id, family, file, sourceUrl, publisher, revision, bytes, sha256, publisherDigest, digestMatch, acquiredAt, licence, licenceUrl, architecture, intendedScope, role}`.
  **Nothing under the quarantine folder is ever loadable**: the adapter refuses any checkpoint path that resolves into it (symbolic links included), and it
  is not the folder rembg reads, so a quarantined file is also never found by a session.
- `python adapter.py quarantine-verify` re-hashes every manifest file and reports a mismatch, a missing file, a missing manifest key or an inconsistent
  `digestMatch`; it exits 1 on any problem.
- `python adapter.py promote <model-id> <asset-file>` copies ONE quarantined asset to `models/models/<model-id>/<file>` (what `/install` and the loader use),
  and only when the registry entry is `admitted`, the file's SHA-256 equals the asset's `pinnedSha256`, and the manifest SHA-256 agrees. Otherwise it exits 1 with the specific reason and copies nothing.
- **Schema 3 admission.** A status of exactly `"admitted"` is valid only if the model is `local`, **every executable asset has a 64-hex `pinnedSha256`**, and the entry has an
  `admission` object `{scope: "internal-evaluation", decision: "admitted", decidedBy, date, evidence[] (at least one reference), checkpointRole, limitations}`.
  `adapter.load_registry` demotes anything else to `invalid-admission` **at load** (with the problems as the reason), and `is_admitted` re-checks before every run.
  `actualSha256` is only an observation; `pinnedSha256` is the authority. `birefnet-general-fp16` has `derivedFrom: "birefnet-general"`: it runs that model's pinned float32 file,
  converted once by rembg, so it needs the source admitted and pinned (limit: rembg's converted copy is not hash-pinned).
- Loading never downloads: while a session is built, `pooch.retrieve` (what rembg uses to fetch files) is refused.
- **Custom checkpoints** (`register-custom`) record their session type and registration time. `customAdmissions` entries must be
  `{sha256, sessionType (u2net_custom|dis_custom|ben_custom), scope: "internal-evaluation", evidence[]}`; a checkpoint runs only if its SHA-256 **and** its registered session type both
  equal one entry. The same hash under another session type, a changed file, or an edited session in the local record is refused (with the reason in the catalogue).
  `GET /catalogue` lists every `custom:<name>` with `name`, `customSession`, `sha256`, `bytes`, `registeredAt`, `customState` (`blocked`/`admitted`), `status` and `blocker`; the Lab shows them,
  selectable only when admitted, installed and ready. The Media Editor offers automatic built-in models only and never lists custom checkpoints.
- **Readiness.** `/catalogue` and `/status` give each model `dependencies` (`ok`, `required`, `missing` module names, `missingPackages`, per-setting `features`) and `ready`, which means
  admitted AND every checkpoint file present AND every module imported by that model importable. `import rembg` itself needs numpy, PIL, onnxruntime, pymatting (+numba), scipy, scikit-image, pooch
  and jsonschema for any model (read from rembg 2.0.88's `bg.py` and `sessions/*.py`; `test_quarantine.ReadinessTest` re-parses the installed sources); `birefnet-general-fp16` adds `onnx` and `onnxconverter_common`.
  A model whose module is missing is `ready: false` with the module named and is refused with 503 before any load.

## Admitted models (PROTO-BGR-RESEARCH-001)

Scope `internal-evaluation` ONLY: not commercial deployment, not redistribution; each `admission.limitations` names the unresolved legal questions (Q-02, Q-04, Q-06, Q-10, Q-12; register in the deliverables folder).

| Model | Why admissible | Files (pinned SHA-256 in `models.json`) |
|---|---|---|
| `birefnet-general-lite` | MIT; rembg's file is byte-identical to the publisher's release ONNX | 1 |
| `birefnet-general` | MIT; rembg's file was verified byte-identical to the publisher's release ONNX by downloading the publisher file | 1 (about 973 MB) |
| `sam` (ViT-B) | Apache-2.0 stated by Meta; the ONNX exports are rembg's hosting, not byte-verifiable against Meta's .pth (recorded limitation) | encoder + decoder, each pinned |

`localFile` (asset field): rembg reads `<session name>.onnx` for every BiRefNet session, not the release file name, so `promote` writes `models/models/birefnet-general/birefnet-general.onnx` from the quarantine file `BiRefNet-general-epoch_244.onnx`.
Install an admitted model: `python adapter.py quarantine-verify`, then `python adapter.py promote <model-id> <asset-file>` per asset.

**Measured on this machine (see `MODEL_BENCHMARK_REGISTER.md`)**: the registry's `ramMbEstimate` (534, 896, 2432 MB) is far below what inference really takes (the resident set reaches about 5 to 8 GB, mostly the first inference's activations), and the adapter checks free RAM
BEFORE it evicts the model that is already loaded, so selecting two models in one Lab run can be refused for memory the swap would free. Use "Unload models" between models (the Lab does this for you in `tests/bgr-real.test.mjs`). The estimate and the preflight were NOT changed; both are recorded as founder decisions.

Tools: `make_synthetic.py` (deterministic authorised test photographs and their ground-truth masks, `fixtures/synthetic/`, plus `--small30` for the 30-photo run);
`smoke.py <model> <evidence folder> [--retry-507 N] [--job-limit-mb N]` (real inference through the adapter, records cold/warm/memory and an RGBA check; no quality score);
`failure_checks.py <evidence folder>` (refusal checks against the real adapter); `bench.py` (isolated child); `../../tests/bgr-real.test.mjs` (the Lab against the real adapter; NOT in `pnpm test`, skips when no adapter).

## Isolated benchmark (IR-045)

`python bench.py --model <id> --image <photo> --out <folder outside the repository> [--runs 3] [--setting only_mask=1]` runs one model on one image in a **fresh child process**: cold load, the first inference
after the load, then N warm inferences, writing one JSON per run (input and output SHA-256, dimensions, provider, checkpoint SHA-256, `coldLoadSeconds`, `inferenceSeconds`, `inferenceIndexSinceLoad`,
`approxModelMemoryMb`, `inferenceRssDeltaMb`, and `isolatedPeakWorkingSetMb`, read with Windows `GetProcessMemoryInfo`, which belongs to that child, i.e. one model, and includes the interpreter and imports; `importBaselineRssMb` lets you read it net).
It uses the adapter's own gate (admitted with pinned hashes, installed and verified, modules importable, RAM and disk preflight) and refuses an unadmitted model; there is no override. It computes no quality score.
The adapter's per-run record and the Lab's JSON and CSV carry the same measurements apart: cold load, first inference after load vs warm, approximate model memory, per-inference RSS change and the **cumulative** process peak (labelled as such, never one model's).

## Start and stop

1. Start the adapter in its own terminal: `.venv\Scripts\python adapter.py`. It prints a **token** for this run.
2. Start the prototype (repo root): `pnpm dev` (open it at `http://127.0.0.1:8443`).
3. Prototype Guide > Experimental Tools > Open the Background Removal Lab, paste the token.
4. Stop the adapter with `Ctrl+C`. A new token is created on every start.

Allowed web origins are ports 8443, 5173 and 4173 on `localhost` / `127.0.0.1` (`ADAPTER_APP_PORTS=8443,9000` adds more).
`ADAPTER_MAX_SESSIONS` (1 or 2, default 1) bounds how many models stay loaded.

## Endpoints

`GET /health`, `GET /catalogue`, `GET /status?model=`, `GET /measurements` (no token; Host and Origin still checked);
`POST /remove?model=&only_mask=&alpha_matting=&post_process_mask=&points=x,y,l;...&cloth=upper|lower|full`,
`POST /unload[?model=]`, `POST /install?model=` (token required). Settings a model does not support, or that conflict
(alpha matting with mask-only), are refused with 400, never ignored. SAM needs at least one foreground point (it is interactive, not
automatic); the cloth model needs an explicit region. There is no default and no fallback model.

## Tests

```
cd tools\bg-removal
.venv\Scripts\python -m unittest test_adapter test_adapter_multi test_adapter_custom test_quarantine -v
```

`test_quarantine` covers schema-3 admission at load, quarantine/promote/quarantine-verify, the absence of any override, readiness, the benchmark gate and the separated measurements.
`test_adapter` starts a real adapter and checks every refusal that must happen before inference. `test_adapter_multi` checks the
registry (23 sessions match rembg's own catalogue; exactly the reviewed models admitted; remote services inactive; `models.json` equals what `build_registry.py -` generates), settings validation and the session
logic (lazy load, bounded cache, unload, SHA-256 verification, RAM preflight, failure isolation) with a **mocked** `rembg` and
temporary files: it proves the adapter's behaviour, not any model's quality. `test_adapter.test_actual_inference_returns_a_real_alpha_png` runs a REAL admitted model when one is installed and RAM allows (it skips with the reason otherwise). `smoke.py` runs real inference. Browser tests: `node tests/run.mjs` in the repo root
(Lab and Media Editor run against a mocked adapter and say so).

## What the adapter checks

Loopback-only binding; `Host` and `Origin` allowlists; a per-run token; no URL or file-path input; models limited to
`models.json`; SHA-256 of every checkpoint file verified before each first load; JPEG, PNG or single-frame WebP only, checked by
actually decoding the image (size is read from the header first); one inference at a time (others get 429); a 60 second response bound.

Known limit: after a timeout or Cancel the browser stops waiting, but native inference cannot be interrupted, so the adapter stays
busy until that image finishes. The prototype ignores any late result.

## BGR-FIX-01..03 additions (PROTO-AUTONOMOUS-003)

- **Colour decontamination** (`decontaminate=1`): rembg 2.0.88's own `decontaminate_cutout`. rembg ignores it when alpha matting is on (matting already estimates the foreground colour), so the adapter refuses the combination, and refuses it with `only_mask`.
- **Alpha matting parameters** (`fg_threshold` 1-255, `bg_threshold` 0-254, `erode_size` 0-50; rembg defaults 240/10/10), valid only with `alpha_matting=1`, foreground above background, images up to 4 megapixels.
- **Verified runtime facts** (read from the installed rembg source): every BiRefNet session, the "dynamic" one included, resizes to a fixed 1024x1024, so rembg exposes no dynamic resolution; the FP16 session converts the float32 file once (needs `onnx` and `onnxconverter-common`, not installed here) and is meant for GPUs; SAM takes `sam_prompt` points/rectangles. `GET /catalogue` now includes a `runtime` block (versions, providers, CPU, RAM, missing requirements).
- **Custom checkpoints**: `python adapter.py register-custom <name> <u2net_custom|dis_custom|ben_custom> <file.onnx>` copies the file into `models/models/custom`, hashes it and lists `custom:<name>` as **blocked**. It runs only after a reviewed `customAdmissions` entry in `models.json` binds its SHA-256 AND its session type (schema 3, above) with evidence. The path passed to rembg as `model_path` is resolved by the adapter (regular file, no symlink, directly inside the custom folder). No HTTP request can name a path or register a file.
- **Recorded per run**: input and output SHA-256, output dimensions, checkpoint SHA-256, the execution provider the session really used, cold/warm flag, RSS before/after load and the load delta (approximate model footprint), and the process-cumulative peak (labelled as such).
- **Official publisher checkpoints** (BiRefNet, SAM) are recorded in `models.json` under `officialPublisher`, separate from the rembg-hosted assets. Nothing was downloaded or compared byte for byte; see MODEL_ADMISSION_REGISTER.
